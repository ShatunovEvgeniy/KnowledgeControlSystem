# ОТЧЁТ
## Автоматизация процесса контроля знаний учащихся

### 1. Введение

В современном образовательном процессе автоматизация контроля знаний становится неотъемлемой частью эффективной организации обучения. Традиционные методы проверки знаний требуют значительных временных затрат преподавателей, подвержены субъективным факторам и затрудняют систематический анализ успеваемости учащихся.

Актуальность разработки системы автоматизированного контроля знаний обусловлена следующими факторами:
- Необходимость объективной оценки знаний учащихся
- Потребность в быстром получении статистики успеваемости
- Экономия времени преподавателей на проверку тестов
- Возможность дистанционного проведения тестирования
- Хранение и анализ исторических данных об успеваемости

В рамках данного проекта разработано полноценное приложение для автоматизированного контроля знаний учащихся с использованием языка программирования Python, системы управления базами данных SQLite и библиотеки Tkinter для создания графического интерфейса.

### 2. Постановка задачи

**Цель разработки:**
Создание информационной системы для автоматизации процесса контроля знаний учащихся, включающей следующие функциональные возможности:
- Регистрация предметов и тестов
- Добавление и учёт учащихся
- Проведение тестирования
- Анализ результатов

**Требования к системе:**

1. **Технические требования:**
   - Хранение данных в реляционной базе данных SQLite
   - Графический интерфейс пользователя на базе библиотеки Tkinter
   - Язык программирования Python 3.7+
   - Кроссплатформенность (Windows, Linux, macOS)

2. **Функциональные требования:**
   - Управление учебными предметами (добавление, просмотр, удаление)
   - Управление вопросами тестов (создание вопросов с 4 вариантами ответов)
   - Учёт учащихся (регистрация, хранение информации)
   - Проведение тестирования в интерактивном режиме
   - Автоматический подсчёт результатов
   - Поиск и анализ результатов по учащемуся и дате

**Структура данных системы:**

1. **Предмет (Subject):**
   - Уникальный идентификатор (subject_id)
   - Название предмета (subject_name)
   - Имя таблицы вопросов (table_name)

2. **Вопрос (Question):**
   - Уникальный идентификатор (question_id)
   - Номер вопроса (question_number)
   - Текст вопроса (question_text)
   - Вариант ответа A (variant_a)
   - Вариант ответа B (variant_b)
   - Вариант ответа C (variant_c)
   - Вариант ответа D (variant_d)
   - Правильный ответ (correct_answer)

3. **Учащийся (Student):**
   - Уникальный идентификатор (student_id)
   - Фамилия (last_name)
   - Имя (first_name)
   - Отчество (patronymic)
   - Группа (group_name)
   - Дата рождения (birth_date)

4. **Результат (Result):**
   - Уникальный идентификатор (result_id)
   - ID учащегося (student_id)
   - ID предмета (subject_id)
   - Количество баллов (score)
   - Общее количество вопросов (total_questions)
   - Процент правильных ответов (percentage)
   - Дата тестирования (test_date)

**Основные правила бизнес-логики:**
- Один тест содержит множество вопросов
- Тесты привязаны к конкретным предметам
- Каждый студент может пройти тест по предмету только один раз
- Поиск результатов осуществляется по учащемуся и дате проведения

### 3. Проектирование системы

#### i. Архитектура системы

Система построена по клиент-серверной архитектуре с локальным хранением данных:

**Backend (Серверная часть):**
- Язык программирования: Python 3.7+
- База данных: SQLite 3
- Модуль работы с данными: knowledgecontrol.py
- Класс: KnowledgeControlSystem

**Frontend (Клиентская часть):**
- Библиотека GUI: Tkinter
- Модуль интерфейса: app_ui.py
- Класс: KnowledgeControlApp

**Архитектурные преимущества:**
- Полная автономность работы (не требует сетевого подключения)
- Простота развёртывания (только интерпретатор Python)
- Надёжное хранение данных в SQLite
- Интуитивно понятный графический интерфейс

#### ii. База данных

База данных SQLite состоит из следующих таблиц:

**Таблица students (учащиеся):**
```sql
CREATE TABLE students (
    student_id INTEGER PRIMARY KEY AUTOINCREMENT,
    first_name TEXT NOT NULL,
    last_name TEXT NOT NULL,
    patronymic TEXT,
    group_name TEXT NOT NULL,
    birth_date TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Таблица subjects (предметы):**
```sql
CREATE TABLE subjects (
    subject_id INTEGER PRIMARY KEY AUTOINCREMENT,
    subject_name TEXT UNIQUE NOT NULL,
    table_name TEXT UNIQUE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Таблица results (результаты тестирования):**
```sql
CREATE TABLE results (
    result_id INTEGER PRIMARY KEY AUTOINCREMENT,
    student_id INTEGER NOT NULL,
    subject_id INTEGER NOT NULL,
    score INTEGER NOT NULL,
    total_questions INTEGER NOT NULL,
    percentage REAL NOT NULL,
    test_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (student_id) REFERENCES students(student_id),
    FOREIGN KEY (subject_id) REFERENCES subjects(subject_id)
);
```

**Таблицы вопросов (создаются динамически для каждого предмета):**
```sql
CREATE TABLE questions_<subjectname> (
    question_id INTEGER PRIMARY KEY AUTOINCREMENT,
    question_number INTEGER NOT NULL,
    question_text TEXT NOT NULL,
    variant_a TEXT NOT NULL,
    variant_b TEXT NOT NULL,
    variant_c TEXT NOT NULL,
    variant_d TEXT NOT NULL,
    correct_answer TEXT NOT NULL CHECK(correct_answer IN ('A', 'B', 'C', 'D')),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Особенности проектирования БД:
- Динамическое создание таблиц вопросов для каждого предмета
- Использование внешних ключей для обеспечения целостности данных
- Автоматическое ведение временных меток
- Уникальные ограничения для предотвращения дублирования

#### iii. Интерфейс пользователя

Графический интерфейс приложения организован в виде трёх вкладок:

**Вкладка 1: "📚 Предметы и вопросы"**
- Форма добавления нового предмета
- Таблица со списком всех предметов

- Таблица вопросов выбранного предмета

**Вкладка 2: "👨‍🎓 Учащиеся и результаты"**

- Поиск студентов по фамилии

**Вкладка 3: "✏️ Проведение тестирования"**

- Автоматический подсчёт баллов и процентов
- Сохранение результатов в базу данных

### 4. Реализация системы

#### 1. Класс KnowledgeControlSystem (Модуль knowledgecontrol.py)

Класс реализует всю бизнес-логику работы с данными системы.

**Конструктор класса:**
```python
def __init__(self, db_path: str = "knowledge_control.db")
```
Инициализирует соединение с базой данных и создаёт таблицы.

**Методы работы с предметами:**

1. `create_tables()` - создаёт таблицы в базе данных
   - Создаёт таблицы: students, subjects, results
   - Не создаёт таблицы вопросов (они создаются при добавлении предмета)

2. `add_subject(subject_name: str) -> Tuple[bool, str]`
   - Параметры: subject_name - название предмета
   - Возвращает: кортеж (успех, сообщение)
   - Создаёт таблицу вопросов для предмета
   - Проверяет на дублирование

3. `get_all_subjects() -> List[Dict[str, Any]]`
   - Возвращает: список словарей с информацией о предметах
   - Сортировка по названию предмета

4. `get_subject_by_id(subject_id: int) -> Optional[Dict[str, Any]]`
   - Параметры: subject_id - ID предмета
   - Возвращает: словарь с информацией или None

5. `delete_subject(subject_id: int) -> Tuple[bool, str]`
   - Удаляет предмет, таблицу вопросов и все результаты

**Методы работы с учащимися:**

1. `add_student(first_name, last_name, group_name, birth_date, patronymic=None) -> Tuple[bool, str]`
   - Параметры:
     - first_name - имя учащегося
     - last_name - фамилия учащегося
     - group_name - название группы
     - birth_date - дата рождения (ГГГГ-ММ-ДД)
     - patronymic - отчество (необязательно)
   - Выполняет валидацию данных
   - Проверяет формат даты

2. `get_student(student_id: int) -> Optional[Dict[str, Any]]`
   - Параметры: student_id - ID учащегося
   - Возвращает: информацию о студенте или None

3. `get_all_students() -> List[Dict[str, Any]]`
   - Возвращает: список всех учащихся
   - Сортировка по фамилии и имени

4. `search_students_by_name(search_term: str) -> List[Dict[str, Any]]`
   - Параметры: search_term - поисковый запрос
   - Поиск по фамилии, имени или отчеству

5. `delete_student(student_id: int) -> Tuple[bool, str]`
   - Удаляет студента и все его результаты

**Методы работы с вопросами:**

1. `add_question(subject_id, question_text, variant_a, variant_b, variant_c, variant_d, correct_answer, question_number=None) -> Tuple[bool, str]`
   - Параметры:
     - subject_id - ID предмета
     - question_text - текст вопроса
     - variant_a...variant_d - варианты ответов
     - correct_answer - правильный ответ ('A', 'B', 'C' или 'D')
     - question_number - номер вопроса (автоинкремент если не указан)

2. `get_questions_by_subject(subject_id: int) -> List[Dict[str, Any]]`
   - Возвращает: все вопросы для указанного предмета

3. `get_question_by_id(subject_id: int, question_id: int) -> Optional[Dict[str, Any]]`
   - Возвращает: конкретный вопрос по ID

4. `delete_question(subject_id: int, question_id: int) -> Tuple[bool, str]`
   - Удаляет вопрос из базы данных

**Методы работы с результатами:**

1. `save_result(student_id, subject_id, score, total_questions) -> Tuple[bool, str]`
   - Параметры:
     - student_id - ID учащегося
     - subject_id - ID предмета
     - score - количество правильных ответов
     - total_questions - общее количество вопросов
   - Автоматически вычисляет процент правильных ответов

2. `get_results_by_student(student_id: int) -> List[Dict[str, Any]]`
   - Возвращает: все результаты тестирования студента
   - Сортировка по дате (новые сначала)

3. `get_results_by_subject(subject_id: int) -> List[Dict[str, Any]]`
   - Возвращает: все результаты по предмету
   - Включает информацию о студентах

4. `has_student_taken_test(student_id: int, subject_id: int) -> bool`
   - Проверяет, проходил ли студент тест по предмету

5. `get_statistics_by_subject(subject_id: int) -> Dict[str, Any]`
   - Возвращает статистику: количество тестов, средний/мин/макс процент

#### 2. Класс KnowledgeControlApp (Модуль app_ui.py)

Класс реализует графический интерфейс приложения на базе Tkinter.

**Конструктор класса:**
```python
def __init__(self, root: tk.Tk)
```
Инициализирует главное окно и создаёт виджеты.

**Основные методы:**

1. `create_widgets()` - создаёт основные виджеты приложения
   - Настраивает стили Tkinter
   - Создаёт контейнер вкладок (Notebook)
   - Инициализирует три вкладки

2. `setup_subjects_tab()` - настраивает вкладку предметов и вопросов
   - Создаёт формы добавления предмета и вопросов
   - Создаёт таблицы для отображения данных
   - Добавляет обработчики событий

3. `setup_students_tab()` - настраивает вкладку учащихся и результатов
   - Создаёт форму регистрации студента
   - Создаёт таблицу студентов
   - Добавляет поиск по фамилии
   - Создаёт таблицу результатов

4. `setup_testing_tab()` - настраивает вкладку проведения тестирования
   - Создаёт выпадающие списки для выбора студента и предмета
   - Создаёт область для отображения вопросов
   - Добавляет кнопки управления тестированием

5. `update_subjects_list()` - обновляет список предметов в таблице
6. `update_questions_list()` - обновляет список вопросов
7. `update_students_list()` - обновляет список студентов
8. `update_results_list(student_id)` - обновляет результаты для студента

9. `add_subject()` - обработчик добавления нового предмета
10. `add_student()` - обработчик добавления нового студента
11. `add_question()` - обработчик добавления нового вопроса
12. `start_test()` - начинает тестирование
13. `save_result()` - сохраняет результаты тестирования
14. `search_results_by_student()` - ищет результаты по фамилии

15. `on_closing()` - обработчик закрытия приложения
    - Корректно закрывает соединение с БД

#### 3. Структура базы данных knowledge_control.db

Полный SQL код создания таблиц:

```sql
-- Таблица учащихся
CREATE TABLE IF NOT EXISTS students (
    student_id INTEGER PRIMARY KEY AUTOINCREMENT,
    first_name TEXT NOT NULL,
    last_name TEXT NOT NULL,
    patronymic TEXT,
    group_name TEXT NOT NULL,
    birth_date TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Таблица предметов
CREATE TABLE IF NOT EXISTS subjects (
    subject_id INTEGER PRIMARY KEY AUTOINCREMENT,
    subject_name TEXT UNIQUE NOT NULL,
    table_name TEXT UNIQUE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Таблица результатов
CREATE TABLE IF NOT EXISTS results (
    result_id INTEGER PRIMARY KEY AUTOINCREMENT,
    student_id INTEGER NOT NULL,
    subject_id INTEGER NOT NULL,
    score INTEGER NOT NULL,
    total_questions INTEGER NOT NULL,
    percentage REAL NOT NULL,
    test_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (student_id) REFERENCES students(student_id),
    FOREIGN KEY (subject_id) REFERENCES subjects(subject_id)
);

-- Таблицы вопросов создаются динамически для каждого предмета
-- Пример для предмета "Математика":
CREATE TABLE IF NOT EXISTS questions_математика (
    question_id INTEGER PRIMARY KEY AUTOINCREMENT,
    question_number INTEGER NOT NULL,
    question_text TEXT NOT NULL,
    variant_a TEXT NOT NULL,
    variant_b TEXT NOT NULL,
    variant_c TEXT NOT NULL,
    variant_d TEXT NOT NULL,
    correct_answer TEXT NOT NULL CHECK(correct_answer IN ('A', 'B', 'C', 'D')),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
